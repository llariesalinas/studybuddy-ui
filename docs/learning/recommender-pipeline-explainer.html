Part 1 — Collaborative Filtering (CF.py)

What is CF?

The core idea: "people like you also liked..."

Collaborative Filtering does not look at tutor content at all (no subjects, no course match). Instead it asks: "Which other students have similar rating patterns to this tutee, and which tutors did those students rate highly?"

If Student A and Student B have both rated the same tutors similarly in the past, they are considered "similar students." When Student A is looking for a new tutor, any tutor that Student B liked (but Student A hasn't used yet) becomes a strong CF signal.

Step 1 of CF — Build the ratings matrix

build_rating_matrix() — CF.py:9

Loads every Rating row from the database and turns it into a nested dict:

ratings = {
  student_id_1: { tutor_id_A: 4.5, tutor_id_B: 3.0, ... },
  student_id_2: { tutor_id_A: 5.0, tutor_id_C: 2.5, ... },
  ...
}

This is built once per request and passed into the hybrid scorer so it isn't re-queried for every tutor.

↓
Step 2 of CF — Find similar students (Pearson similarity)

sim() + top_k() — CF.py:31 / CF.py:64

For the current tutee, find the 5 students (k=5) whose rating patterns are most similar, using Pearson correlation. Pearson is chosen over simpler cosine similarity because it accounts for rating bias — a student who always rates 5/5 and one who always rates 3/5 can still be "similar" if they agree on which tutors are relatively better.

# Pearson similarity between student u and student v: # only computed over tutors both students have rated (common set) sim(u, v) = Σ (r_ui - r_u_avg)(r_vi - r_v_avg) ──────────────────────────────────────── √Σ(r_ui - r_u_avg)² · √Σ(r_vi - r_v_avg)² # Result is between -1 (opposite taste) and +1 (identical taste) # Returns 0 if no common tutors rated (no basis for comparison)

top_k() runs this against every other student in the matrix and returns the top 5 by similarity score. These are the "neighbors."

↓
Step 3 of CF — Predict a rating for each candidate tutor

compute_cf_score() — CF.py:88

For each candidate tutor, predict what the current tutee would likely rate them, based on how similar neighbors rated that tutor — adjusted for each neighbor's personal rating baseline.

# Weighted average of neighbor ratings, adjusted for baseline: predicted_rating = student_avg + Σ sim(u, neighbor) × (r_neighbor_tutor - neighbor_avg) ────────────────────────────────────────────────────── Σ |sim(u, neighbor)| # student_avg = this tutee's average rating across all their past sessions # Returns None if no neighbor has rated this tutor (no CF signal)

A None result means there is no collaborative data for this tutor/student pair — the hybrid scorer treats this as 0, falling back to purely CBF for that tutor.

Important — the cold start problem

New students get 0% CF influence

If a tutee has never completed a session, they have no entries in the ratings matrix (student_id not in ratings). compute_cf_score returns None immediately, which hybrid.py converts to 0.

This means for a brand-new tutee the hybrid is effectively 100% Content-Based Filtering — tutor recommendations are driven entirely by subject/course match. CF's weight grows naturally as the student completes sessions and ratings accumulate. No special handling is needed; it's automatic.

# New student (0 sessions): hybrid_score = 0.7 × cbf_score + 0.3 × (0 / 5) → pure CBF # Returning student (has ratings + similar neighbors found): hybrid_score = 0.7 × cbf_score + 0.3 × (cf_score / 5) → blended

Step 3 — Scoring

recommend_tutors_hybrid (hybrid.py:62)

Every tutor surviving Step 2 is scored using the blended formula. Two signals run independently and are combined:

CBF — Content-Based Filtering
cbf.py: compute_cbf_score

"Does this tutor teach what the student needs?" Weighted similarity across subject match, course, year level, and strand/level. Always produces a score — no cold-start problem.

70% of final score

CF — Collaborative Filtering
CF.py: compute_cf_score

"How have similar students rated this tutor?" Pearson-weighted prediction from k=5 nearest neighbors in the rating matrix. Returns 0 when student has no rating history (cold start).

30% of final score (scaled ÷5)

hybrid_score = 0.7 * cbf_score + 0.3 * (cf_score / 5)
↓
Step 4 — Response

Ranked list returned to FindTutors.vue

Tutors sorted by hybrid_score descending, serialized, and rendered as tutor cards.

Replaced by: hybrid.py::recommend_tutors_hybrid

Replaced by: hybrid.py::recommend_tutors_hybrid

What this means for the institution filter plan: If we only patch the live pipeline (get_recommendation_candidate_tutors in views.py and the dashboard candidate queryset), the dead functions are harmless — nothing calls them so they can never expose cross-institution tutors.
