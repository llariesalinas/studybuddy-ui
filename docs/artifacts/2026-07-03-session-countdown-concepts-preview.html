Session countdown prototype

Three reactive directions for the new session status bar

The goal for MVP is a scheduled-window countdown that appears 15 minutes before start, stays visible during the live session, then becomes the post-session handoff until that handoff is done. This prototype only answers the UI question.

1
Prototype the surfaces Compare three animated concepts in local HTML, with the same states we expect in app: upcoming, live, and handoff.
2
Implement the chosen language in two places Full status bar on the session detail page, compact dock everywhere else, hidden when you are already on that session detail route.
3
Wire real queue and countdown data Use the scheduled session window, current live session, handoff priority, and next upcoming session hint from shared store state.

Clock rule: countdown is tied to the scheduled session window, not to arrival.
MVP priority: current live session or handoff beats the next session in queue.
Readiness later: hold-to-confirm can layer in after we like the countdown surface.

Implementation plan after we choose a direction

1. Shared session queue state Build one store or composable that chooses whether the front item is live session, handoff, or next upcoming within 15 minutes.
2. Two surfaces, one language Render the same state in a full-width bar on session detail pages and a compact bottom dock everywhere else.
3. Readiness as a separate layer Add hold-to-confirm later as supporting state, never as the thing that starts or stops the official timer.
