Reset & Seed Commands

Local/dev only, from backend/:
venv\Scripts\python.exe manage.py reset_demo_data
venv\Scripts\python.exe manage.py seed_data

reset_demo_data deletes every non-staff user (cascading profiles, tutors, bookings, wallets, ratings, applications, chat, …), the subject catalog, and platform activity, while preserving staff/SuperAdmin logins. seed_data refuses to run if any non-staff data still exists, so the two commands always run in that order. Re-running the pair is safe and reproduces the same personas and scores (fixed seed 20260716), plus the 2 SuperAdmin accounts and all 3 additive demo cases above — a single reset_demo_data && seed_data is now the complete recipe for a fully demoable database, on local dev or the live Render demo deployment.

Draining the async email queue

Verification approval/rejection, document renewal reminder/result, booking confirmed, and password-changed-notice emails are queued via Django-Q and only actually send when something consumes that queue — nothing does automatically yet (no qcluster worker is deployed). Login OTP and password reset are unaffected; both send synchronously. Drain the backlog by hand from a Render Shell session, from backend/:
python manage.py qcluster --run-once

Processes every currently-queued task once, then exits — safe to re-run any time. See async email worker reliability for the full diagnosis and the still-open follow-up (an automated Render Cron Job on the same command, so this stops being a manual step).

Seeding an additional SuperAdmin

The 2 SuperAdmin accounts above are seeded automatically — you only need this section for a third custom account (e.g. a named reviewer login), or to promote an already-registered user. Use make_superadmin from backend/:

If the account already exists, just promote it — this never touches the password:
venv\Scripts\python.exe manage.py make_superadmin someone@cpu.edu.ph

If no account exists yet for that email, add --create — it prompts twice for a password via hidden input (never logged or echoed):
venv\Scripts\python.exe manage.py make_superadmin someone@cpu.edu.ph --create --first-name First --last-name Last

To run either form against the demo/production database instead of local dev, point the same session at the demo Supabase pooler first (see demo deployment cheat sheet, "Running a one-off command against the demo database") — never hardcode that database's password into a single command; set it as a session env var and unset/close the terminal afterward.
