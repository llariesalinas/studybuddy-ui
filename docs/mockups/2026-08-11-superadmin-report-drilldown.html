Decisions this mockup encodes

  • Cards keep their top-5 summary. "Top performers" stays an honest name, and the destination is "Tutor performance" — deliberately not "All tutors". The query is booking-driven, so a tutor idle in the window is absent entirely. The count is period-dependent: 23 tutors at 7d, 125 at 30d, 159 at 90d and all time.
  • No zero-filled roster. Showing all 163 tutors with zeros was rejected — the Users tab already is the full roster. Reports earns its place on earnings and period scoping, which Users has nowhere.
  • No rank column. The sessions figure is already visible and sortable; a rank adds nothing and is the one column whose meaning breaks on re-sort.
  • Null ratings sort last in both directions. One tutor has completed sessions but no rating; treating that as 0 would rank them below a genuine 1-star tutor, which the data does not support.
  • Filters travel in the query string — ?period=&institution=. The destination shows the same slice as the card clicked, Back restores the dashboard's filters, refresh survives, and the URL is shareable.
  • Period chips and Export repeat on the detail page, so the page is usable as a destination in its own right rather than only as a pop-out.
  • Subjects become a sortable table with a share-of-bookings column. The dashboard's bar-track visual does not survive 106 rows; a percentage column carries the same meaning and sorts.
  • Sorting is client-side over the loaded array. At 159 and 106 rows there is nothing to gain from server-side sort.
  • Whole page scrolls — no inner scroll region, so Ctrl+F and printing both work.
