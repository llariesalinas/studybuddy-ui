Decision artifact · 2026-08-20

Sidebar mode switcher — segmented control

Chosen from three options after the existing control was confirmed to render unstyled: SbModeSwitcher.vue is a multi-root fragment, so Vue never applies AppSidebar.vue's scope id to it, and .sb-item / .sb-chip / .sb-item-label exist only inside that scoped block. Verified by mounting the real component and comparing rendered attributes against the Log out button.

The replacement is a two-cell segmented control that shows the current mode and switches to the other, placed above the footer divider so Log out gets its width back.

Why this placement

  • Sits above the .sb-footer border, so it leaves the footer's justify-content: space-between row untouched — Log out stops competing for width and its label stops clipping.
  • Uses the system's default interactive shape: a 999px pill, per DESIGN.md's Pill-Or-Card Rule.
  • Selection is a filled cell rather than an outline because the two cells are mutually exclusive segments, not independent filter pills.
  • Every colour is an existing token: --sb-bg, --sb-card-border, --sb-primary, --sb-text-muted.

Collapsed behaviour

  • Stacks vertically, matching .sb-sidebar--collapsed .sb-footer, which already switches to flex-direction: column.
  • Keeps two-letter labels rather than collapsing to a single arrow icon. This is the whole reason this option was chosen: an unlabelled bi-arrow-left-right chip is indistinguishable from sync or refresh.
  • Each cell carries a title and the full mode name as its accessible name; the visible TE / TR is a visual abbreviation only.

Unprovisioned mode — setup dialog

You currently don't have a Tutor account. Setting one up takes a few steps, and you can switch back any time — your existing Tutee account stays exactly as it is. Your documents are already verified, so you won't need to upload them again.

Accessibility contract shipped with this control

  • The dialog gets an aria-labelledby pointing at its heading — today it declares role="dialog" and aria-modal="true" with no accessible name (WCAG 4.1.2).
  • Escape closes it; focus moves into the dialog on open, is trapped while it is open, and returns to the segment that opened it on close (WCAG 2.1.2 / 2.4.3).
  • The busy state is announced rather than only swapping a label to Switching….
  • Focus is not dropped mid-switch: the group is marked busy instead of the focused cell being disabled out from under the user.
  • Decorative icons carry aria-hidden="true".
  • Arrow keys move between segments and the group exposes a single tab stop, per the radiogroup pattern.

Known tradeoff

A segmented control implies switching is instant. For a user whose other mode is not provisioned, the first activation opens the setup dialog instead — the selected cell must not move until the switch actually succeeds, or the control will lie about state.
