# Vercel for frontend, Render for backend, Supabase for the database

The Django backend uses Channels for chat ([consumers.py](../../backend/studybuddy/chat/consumers.py)), which needs a host that keeps a persistent WebSocket connection open — this rules out serverless-only platforms (e.g. Vercel serverless functions) for the backend. We chose Vercel for the Vite/Vue frontend (free tier, zero-config Vite builds, native per-branch deploys) and Render for the backend + worker process (WebSocket support, native per-branch deploy targets, hobby-tier pricing suitable for a demo).

**Superseded (2026-07-05):** Postgres is hosted on Supabase, not Render, so the database survives independently of the app host (a Render redeploy, restart, or plan change never touches the data) and each environment gets its own dedicated Supabase project rather than a Render-managed add-on. Redis (if needed for caching/Channels) is provisioned separately, since Supabase does not provide it. `main` and `develop` each get their own Vercel deployment, Render service, and Supabase project.
